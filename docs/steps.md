# Password Manager: Цифровой сейф в мире киберпанка

## 1 Модель записи

### Контекст

Начнём с фундамента: для хранения одной записи пароля — сервис, значение пароля, категория и временные метки. Все последующие функции будут работать с экземплярами этой структуры. Для сохранения в файл понадобится сериализация в JSON — в Go для этого к полям добавляют теги json:"имя_поля".

### Ключевая концепция: JSON и теги структур

JSON (JavaScript Object Notation) — текстовый формат данных в виде пар «ключ: значение». В Go структура сериализуется в JSON через json.Marshal; имена ключей в JSON задаются тегами, например `json:"name"`. Поля с заглавной буквы экспортируются (видны другим пакетам) и попадают в JSON; NewPassword гарантирует корректную инициализацию полей, включая время.
Цели этапа

Создать структуру Password и конструктор NewPassword.

Что необходимо сделать:

    1. Создать структуру Password с полями:
        Name (string) — название сервиса или сайта
        Value (string) — значение пароля
        Category (string) — категория для группировки (например: "social", "work", "finance")
        CreatedAt (time.Time) — дата создания записи
        LastModified (time.Time) — дата последнего изменения

    2. Добавить теги json ко всем полям структуры для сериализации в файл (например, `json:"name"`).

    3. Создать конструктор:

    func NewPassword(name, value, category string) Password

        Устанавливать CreatedAt и LastModified через time.Now().
        Возвращать заполненную структуру (значение, не указатель).

### Пример работы

Ожидаемый вывод при сериализации структуры Password в JSON (через json.Marshal):

{"name":"github.com","value":"superSecretPassword123","category":"development","created_at":"2024-11-24T15:04:05Z","last_modified":"2024-11-24T15:04:05Z"}

## 2 Ядро менеджера

### Контекст

В мире киберпанка недостаточно просто создать защищенное хранилище - нужен умный менеджер, который будет этим хранилищем управлять. Структура PasswordManager станет главным координатором всех операций в нашей системе.

Этот менеджер будет не просто хранить пароли - он будет отвечать за их шифрование, организацию и безопасный доступ. Представьте его как высокотехнологичный сейф с продвинутой системой управления. В одних руках он может быть электронным хранилищем корпоративных секретов, в других - персональным менеджером паролей обычного нетраннера.

В общей архитектуре проекта PasswordManager играет центральную роль - все операции с паролями будут проходить через него, и он будет гарантировать их безопасность и согласованность.

### Цели этапа

Создать структуру PasswordManager и конструктор NewPasswordManager.

Что необходимо сделать:

    Поля: passwords (map[string]Password) — хранилище, ключ — имя сервиса, с JSON-тегами; masterKey ([]byte), filePath (string), isInitialized (bool) — с тегом json:"-" (не сериализовать). В Go поля с маленькой буквы видны только внутри пакета (приватные).
    Конструктор func NewPasswordManager(filePath string) *PasswordManager — инициализировать пустую через , сохранить путь, флаг false. Возвращает на структуру — это позволяет методам изменять поля менеджера.

### Пример работы

Ожидаемый вывод после создания NewPasswordManager("passwords.dat") и вывода начального состояния:

```shell
Initialized: false
File path: passwords.dat
Passwords count: 0
```

## 3 Защита хранилища

### Контекст

В мире киберпанка мастер-ключ — это не просто пароль, это ключ к вашему цифровому убежищу. Функция SetMasterPassword — критически важный компонент безопасности, который превращает обычный менеджер паролей в защищённое хранилище.

#### Зачем нужен мастер-пароль:

    Используется для шифрования данных и проверки их целостности
    Никогда не хранится в открытом виде
    Используется для генерации ключа шифрования
    Минимальная длина 8 символов обеспечивает базовую защиту от брутфорса

В нашей реализации мы преобразуем пользовательский мастер-пароль в слайс байт фиксированной длины 32 байта, потому что в следующих этапах нам потребуется симметричное шифрование AES-256, а оно требует ключ именно такой длины. Если пароль короче — оставшееся место заполнится нулями, если длиннее — возьмутся только первые 32 байта.

В общей архитектуре SetMasterPassword является первым шагом к безопасной работе с менеджером. Все последующие операции с паролями будут проверять, что менеджер правильно инициализирован через эту функцию. Именно поэтому мы реализуем её до SavePassword и GetPassword.

### Используемые пакеты

Пакет	Что используем	Зачем
builtin	make, copy	Создание байтового буфера и копирование данных


### Цели этапа

Создать функцию установки мастер-пароля (ключ для AES-256).

#### Что необходимо сделать:

    Сигнатура: func (pm *PasswordManager) SetMasterPassword(masterPassword string) .

    Запись (pm *PasswordManager) перед именем функции — это с получателем (receiver). pm — имя переменной, через которую вы обращаетесь к полям структуры (pm.masterKey, pm.isInitialized). Звёздочка * означает указатель: метод получает ссылку на оригинальный объект и может менять его поля. Без * метод получил бы копию, и изменения не сохранились бы.

#### Логика:

    Проверить длину мастер-пароля: минимум 8 символов. Если короче — вернуть ошибку (например, «password is too weak»).
    Создать буфер под ключ: — make([]byte, 32) — 32 байта для AES-256.
    Скопировать байты пароля в буфер через copy(dst, []byte(masterPassword)). Если пароль короче 32 байт, остаток останется нулевым; если длиннее — скопируются только первые 32 байта.
    Сохранить ключ в поле pm.masterKey.
    Установить флаг pm.isInitialized = true. После этого можно сохранять и загружать пароли.

### Пример работы

Ожидаемый вывод при коротком и корректном мастер-пароле:

```shell
Weak master password: password is too weak
Strong master password: <nil>
Manager initialized: true
Master key length: 32
```

    ⚠️ **Важно: Использование пароля напрямую как ключа AES — упрощение для учебных целей. В production используют KDF (Key Derivation Function), например scrypt или argon2, для безопасного преобразования пароля в ключ.**
